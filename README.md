# nfc-figurines

Подставка для статуэток под Home Assistant. В основании каждой статуэтки — метка NFC.
Статуэтку ставят на подставку — HA запускает назначенный ей сценарий и зажигает кольцо
подсветки её цветом. Что делает каждая статуэтка, каким цветом и сколько секунд светит,
владелец настраивает сам в приложении Home Assistant.

- `esphome/figurki.yaml` — прошивка устройства.
- `esphome/figurki.h` — соответствие UID метки → номер статуэтки.
- `esphome/nfc-bench.yaml` — стенд: только чтение меток, UID в лог по USB.
- `blueprints/figurine.yaml` — блупринт HA «Статуэтка → сценарий и подсветка».

## Детали

| Что | Сколько |
| --- | --- |
| ESP32 DevKitC, 38 пинов, WROOM-32 | 1 |
| PN532 V3 (переключатели I²C/SPI/HSU) | 1 |
| Метки NTAG215, диск Ø25 мм | 10 |
| Адресная лента 5 В, WS2812B, 60 пикселей/м — кольцо 24 пикселя | 40 см |
| SN74AHCT125N — сдвиг уровня данных 3.3 → 5 В | 1 |
| Конденсатор 1000 мкФ 16 В | 1 |
| Резистор 220 Ом | 1 |

Кольцо: 24 пикселя × 16.7 мм = 400 мм ленты — окружность Ø ≈ 127 мм по поверхности
светодиодов. Круг больше — только резать по пикселю и соединять проводами. Шаг
пикселя перед проектированием корпуса замерить на реальной ленте.

## Подключение

**PN532 по SPI.** Переключатели на плате: 1 — OFF, 2 — ON (переключать без питания).

| PN532 | ESP32 |
| --- | --- |
| SCK | GPIO18 |
| MISO | GPIO19 |
| MOSI | GPIO23 |
| SS | GPIO5 |
| VCC | 3V3 |
| GND | GND |

IRQ и RSTO не подключаются.

**Кольцо через 74AHCT125** (DIP-14, ключ — вывод 1):

```
                 74AHCT125, вид сверху
                      ┌───∪───┐
  GND ─────────── 1 1OE│       │VCC 14 ─────── +5V
  ESP32 GPIO16 ── 2 1A │       │4OE 13 ─────── +5V
  к резистору ◀── 3 1Y │       │4A  12 ─────── GND
  +5V ─────────── 4 2OE│       │4Y  11   —
  GND ─────────── 5 2A │       │3OE 10 ─────── +5V
           —      6 2Y │       │3A   9 ─────── GND
  GND ─────────── 7 GND│       │3Y   8   —
                      └───────┘

  вывод 3 ──[ 220 Ом ]────────────── Din ┐
                                         │
  +5V ──────────┬──────────────────── +5V │ лента, 24 пикселя
                │ +  (длинная нога)       │ (стрелки — от проводов)
            1000 мкФ                      │
                │ −  (полоска)            │
  GND ──────────┴──────────────────── GND ┘

  ESP32: 5V → шина +5V, GND → шина GND, GPIO16 (бывает подписан RX2) → вывод 2.
  PN532 остаётся как был: 3V3 и SPI.
```

| Откуда | Куда |
| --- | --- |
| ESP32 GPIO16 | вывод 2 (1A) |
| вывод 3 (1Y) | 220 Ом → DIN ленты |
| вывод 1 (1OE) | GND |
| вывод 14 (VCC) | 5V |
| вывод 7 (GND) | GND |
| выводы 5, 9, 12 (неиспользуемые входы) | GND |
| выводы 4, 10, 13 (неиспользуемые OE) | 5V |
| +5V и GND ленты | 5V и GND ESP32, 1000 мкФ между ними у входа ленты |

Питание — блок 5 В / 2 А через отдельное гнездо USB-C: от гнезда 5 В идёт параллельно на
ленту и на пин 5V ESP32, разъём USB самой ESP32 — только для прошивки (оба сразу не
подключать). Худший случай, полный белый: кольцо 24 × 60 мА × 80 % ≈ 1.15 А + ESP32 до
0.35 А + PN532 0.15 А ≈ 1.65 А. Отсюда потолок яркости 80 % в `figurki.yaml`. Стенд
питается через USB ESP32 (номинал защитной детали между разъёмом и пином 5V неизвестен),
поэтому в `nfc-bench.yaml` потолок 50 %.

## Стенд: считать метки

```
cd esphome && uvx --python 3.12 esphome run nfc-bench.yaml
```

Поднести метку — в логе `ПОСТАВИЛИ: 04-…`. UID каждой метки вписать в `figurki.h`
(`{"04-…", "figurka-1"}`), номер подписать на основании статуэтки.

## Что показал стенд (20.10.2026)

- Связь ESP32 ↔ PN532 по SPI чистая: 1513 подтверждений подряд без ошибок. Сбои
  «Requesting tag read failed» были только пока трогали дюпоны.
- Карта из комплекта держится на ридере постоянно. Диск Ø25 мм в неудачном
  положении читается один раз в момент укладки и дальше не находится: PN532
  не успевает найти метку за 100 мс (порог в коде ESPHome). В рабочем положении
  держится десятки секунд.
- Даже в рабочем положении ридер изредка пропускает один опрос, а ESPHome
  считает это снятием. Поэтому снятие подтверждается только через 1.5 с без метки.
- Живой экран стенда: `python3 tools/bench-viewer.py <лог> 8765` → http://localhost:8765
  (нужна отладочная прошивка с `logger: level: VERBOSE`).

## Прошивка устройства

```
cd esphome && uvx --python 3.12 esphome run figurki.yaml
```

## Для владельца

1. Включить подставку. С телефона подключиться к Wi-Fi **Figurki Setup**, на открывшейся
   странице выбрать свою сеть и ввести пароль.
2. Home Assistant сам покажет «Обнаружено: Статуэтки» — **Добавить**.
3. Импортировать блупринт:
   [![Импорт блупринта](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2Frudnik275%2Fnfc-figurines%2Fblob%2Fmain%2Fblueprints%2Ffigurine.yaml)
4. **Настройки → Автоматизации → Создать → из блупринта «Статуэтка → сценарий и
   подсветка»** — по одной автоматизации на статуэтку: статуэтка, кольцо, цвет, эффект,
   сколько секунд светить (0 — пока стоит), что сделать, когда поставили и когда сняли.

Если кольцо мигнуло красным — подставка не связана с Home Assistant (Wi-Fi или HA
недоступны), метка при этом прочитана.

Свои метки NTAG215 тоже работают: первая же поставленная появится в **Настройки →
Метки** со своим UID, его можно вписать в поле «Статуэтка».
