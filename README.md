# nfc-figurines

Подставка для статуэток под Home Assistant. В основании каждой статуэтки — метка NFC.
Статуэтку подносят — кольцо заполняется с двух сторон по мере того, как ридер всё
увереннее видит метку; поставили — кольцо «вдыхает», горит её цветом и плавно гаснет,
а HA запускает её сценарий. Цвет, время свечения и сценарий каждой статуэтки владелец
настраивает сам в приложении Home Assistant.

- `esphome/figurki.yaml` — прошивка устройства.
- `esphome/ring_engine.h` — анимация кольца, чистый C++; тесты — `tests/ring_engine_test.cpp`.
- `esphome/figurki.h` — соответствие UID метки → номер статуэтки.
- `esphome/nfc-bench.yaml` — стенд: только чтение меток, UID в лог по USB.
- `blueprints/figurine.yaml` — блупринт HA «Статуэтка → цвет и сценарий».
- `docs/s/index.html` — страница настройки для владельца (QR №2), GitHub Pages.
- `docs/stickers/sticker-50x30.png` — наклейка на корпус для Niimbot B1, `tools/make-sticker.py`.

## Детали

| Что | Сколько |
| --- | --- |
| ESP32 DevKitC, 38 пинов, WROOM-32 | 1 |
| PN532 V3 (переключатели I²C/SPI/HSU) | 1 |
| Метки NTAG215, диск Ø25 мм | 10 |
| Адресная лента 5 В, WS2812B, 60 пикселей/м — кольцо 24 пикселя | 40 см |
| SN74AHCT125N — сдвиг уровня данных 3.3 → 5 В | 1 |
| Керамика 0.1 мкФ (`104`): у 74AHCT125, у входа ленты, на GPIO34 и GPIO35 | 4 |
| Резистор 100 кОм — в линии CC1 и CC2 | 2 |
| Гнездо USB-C на платке с площадками CC1/CC2 | 1 |
| Резистор 220 Ом | 1 |

Кольцо: 24 пикселя × 16.7 мм = 400 мм ленты — окружность Ø ≈ 127 мм по поверхности
светодиодов. Круг больше — только резать по пикселю и соединять проводами. Шаг
пикселя перед проектированием корпуса замерить на реальной ленте.

## Подключение

**PN532 по SPI.** Переключатели на плате: 1 — OFF, 2 — ON (переключать без питания).

| PN532 | ESP32 |
| --- | --- |
| SCK | GPIO18 |
| MISO | GPIO19 |
| MOSI | GPIO23 |
| SS | GPIO5 |
| VCC | 3V3 |
| GND | GND |

IRQ и RSTO не подключаются.

**Кольцо через 74AHCT125** (DIP-14, ключ — вывод 1):

```
                 74AHCT125, вид сверху
                      ┌───∪───┐
  GND ─────────── 1 1OE│       │VCC 14 ─────── +5V
  ESP32 GPIO16 ── 2 1A │       │4OE 13 ─────── +5V
  к резистору ◀── 3 1Y │       │4A  12 ─────── GND
  +5V ─────────── 4 2OE│       │4Y  11   —
  GND ─────────── 5 2A │       │3OE 10 ─────── +5V
           —      6 2Y │       │3A   9 ─────── GND
  GND ─────────── 7 GND│       │3Y   8   —
                      └───────┘

  вывод 3 ──[ 220 Ом ]────────────── Din ┐
                                         │
  +5V ──────────┬──────────────────── +5V │ лента, 24 пикселя
                │                         │ (стрелки — от проводов)
          керамика 104                    │
                │  (полярности нет)       │
  GND ──────────┴──────────────────── GND ┘

  ESP32: 5V → шина +5V, GND → шина GND, GPIO16 (бывает подписан RX2) → вывод 2.
  PN532 остаётся как был: 3V3 и SPI.
  Электролит 1000 мкФ не ставить: умные зарядники USB-C видят бросок тока на его
  зарядку как перегрузку и уходят в защиту (пуск — отбой раз в секунду).
```

| Откуда | Куда |
| --- | --- |
| ESP32 GPIO16 | вывод 2 (1A) |
| вывод 3 (1Y) | 220 Ом → DIN ленты |
| вывод 1 (1OE) | GND |
| вывод 14 (VCC) | 5V |
| вывод 7 (GND) | GND |
| выводы 5, 9, 12 (неиспользуемые входы) | GND |
| выводы 4, 10, 13 (неиспользуемые OE) | 5V |
| +5V и GND ленты | шины +5V и GND, керамика 104 между ними у входа ленты |
| вывод 14 и вывод 7 | керамика 104 вплотную к ним |
| CC1 / CC2 гнезда USB-C | 100 кОм → GPIO34 / GPIO35, у каждого пина керамика 104 на GND |

Питание — блок 5 В / 2 А через отдельное гнездо USB-C: от гнезда 5 В идёт параллельно на
ленту и на пин 5V ESP32, разъём USB самой ESP32 — только для прошивки (оба сразу не
подключать). Худший случай, полный белый: кольцо 24 × 60 мА × 80 % ≈ 1.15 А + ESP32 до
0.35 А + PN532 0.15 А ≈ 1.65 А. Отсюда потолок яркости 80 % в `figurki.yaml`. Стенд
питается от USB компьютера через разъём ESP32 (номинал защитной детали между разъёмом и
пином 5V неизвестен), поэтому в `nfc-bench.yaml` потолок 25 %: всё вместе меньше 1 А.

## Стенд: считать метки

```
cd esphome && uvx --python 3.12 esphome run nfc-bench.yaml
```

Поднести метку — в логе `ПОСТАВИЛИ: 04-…`. UID каждой метки вписать в `figurki.h`
(`{"04-…", "figurka-1"}`), номер подписать на основании статуэтки.

## Что показал стенд (20.10.2026)

- Связь ESP32 ↔ PN532 по SPI чистая: 1513 подтверждений подряд без ошибок. Сбои
  «Requesting tag read failed» были только пока трогали дюпоны.
- Карта из комплекта держится на ридере постоянно. Диск Ø25 мм в неудачном
  положении читается один раз в момент укладки и дальше не находится: PN532
  не успевает найти метку за 100 мс (порог в коде ESPHome). В рабочем положении
  держится десятки секунд.
- Даже в рабочем положении ридер изредка пропускает один опрос, а ESPHome
  считает это снятием. Поэтому снятие подтверждается только через 1.5 с без метки.
- Живой экран стенда: `python3 tools/bench-viewer.py <лог> 8765` → http://localhost:8765
  (нужна отладочная прошивка с `logger: level: VERBOSE`).

## Прошивка устройства

Ключ шифрования лежит в приватном `rudnik275/nfc-figurines-private` и подключается симлинком:

```
ln -s ../../nfc-figurines-private/secrets.yaml esphome/secrets.yaml
```

```
cd esphome && uvx --python 3.12 esphome run figurki.yaml
```

Яркость ограничивать вручную не нужно: подставка читает с линий CC гнезда USB-C
(GPIO34/35 — каждая через резистор 100 кОм и с керамикой 0.1 мкФ на GND у пина: напрямую
выключенная ESP32 через защитные диоды садит CC, и зарядники с 3 А не подают питание), сколько готов отдать зарядник — 3 А, 1.5 А или «по умолчанию», — и держит
оценку тока кольца в этом бюджете (`limit_power` в `ring_engine.h`). От USB компьютера
через разъём ESP32 гнездо пустое — кольцо само становится тусклым. Что распознано —
датчик «Блок питания» в HA и строка `power` в логе.

Сброс к заводским (забыть Wi-Fi, снова «Figurki Setup»): 5 раз подряд включить питание,
каждый раз не дольше 10 с, или кнопка «Сброс к заводским» в HA. Сменили Wi-Fi —
сбрасывать не обязательно: не найдя старую сеть, подставка через минуту сама поднимает
«Figurki Setup».

Тесты анимации (на macOS clang не находит libc++ сам — путь к SDK указан явно):

```
SDK=$(xcrun --show-sdk-path); clang++ -std=c++17 -isysroot "$SDK" -nostdinc++ -isystem "$SDK/usr/include/c++/v1" -I esphome tests/ring_engine_test.cpp -o /tmp/rt && /tmp/rt
```

Настройки анимации — поля в начале `RingEngine` (`ring_engine.h`): скорость заполнения,
глубина вдоха, время затухания, `start` — пиксель, от которого расходятся волны.

## Для владельца

Пошагово — на странице настройки: https://rudnik275.github.io/nfc-figurines/s/ (QR №2 на
наклейке). Коротко: Wi-Fi через QR №1 → «Обнаружено: Статуэтки» в HA, ключ шифрования →
блупринт → по автоматизации на статуэтку.

Импорт блупринта:
[![Импорт блупринта](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2Frudnik275%2Fnfc-figurines%2Fblob%2Fmain%2Fblueprints%2Ffigurine.yaml)

Кольцо на пустой платформе: дышит синим — нет Wi-Fi; янтарным — нет связи с HA (первые
15 минут после включения); метка загорелась белым — для неё нет автоматизации.
